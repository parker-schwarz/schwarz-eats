How the 1.25× scale works: The app uses initial-scale=1.25 without width=device-width, so every phone's CSS layout viewport is device-width ÷ 1.25. On an iPhone 14 (390 px device-width), the app's CSS sees 312 px — that's what controls all the layout math. The iframes below use those exact viewport widths, so you're seeing the true CSS layout for each device.
iOS — Standard OS Zoom

iPhone — OS Display set to Standard

With the phone's Settings → Display & Brightness → View → Standard, the device reports its full device-width. The app divides that by 1.25, giving the CSS viewport below each frame.

iOS — OS "Zoomed" Display Mode

iPhone — OS Display set to Zoomed

Settings → Display & Brightness → View → Zoomed tells iOS to report a smaller device-width (e.g. iPhone 14 drops from 390 px to ~320 px), making everything appear larger. The app's own 1.25× scale then stacks on top, compressing the layout viewport further. Layouts can feel cramped — cards get narrower, text may wrap earlier.

Android — Standard Display Size

Android Phones — Default Display Settings

Android device-widths vary more than iOS. The app's 1.25× scale applies the same way. Wider devices (Pixel) give the cards more room; compact devices (S24) are tighter. Android does not have a universal "Zoomed" display mode like iOS.
